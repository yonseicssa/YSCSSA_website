# YSCSSA 网站维护手册

面向内容维护人员（不需要写代码）。技术性说明见仓库根目录 `README.md`。

## 一、进入后台

1. 点导航栏右上角的**「登录」**按钮，或直接打开 `https://<域名>/admin`
2. 用**自己的 GitHub 账号**登录（不要共用账号：所有修改都会记到操作人名下）
3. 左侧是内容分类：活动、新生指南、页面文案、组织架构、全站设置

保存后系统自动构建，**1–2 分钟后线上生效**。刷新页面即可看到。

## 二、常用操作

### 新增一场活动

1. 左侧「活动」→ 右上角「New 活动」
2. 填写：
   - **标题**：建议 20 字以内
   - **开始日期**：必填。**网址由它自动生成**（例：2026-09-25 → `/events/2026-09-25`）
   - **结束日期**：只有跨天活动才填，单日活动留空
   - **地点**、**封面图**（16:9）、**封面图说明文字**（必填，给读屏软件和搜索引擎看）
   - **正文**：活动介绍、报名方式等
3. 保存 → 发布

> 活动是「即将举行」还是「已结束」由网站自动判断，不需要手动改。
> 活动没有「置顶」开关——要重点推荐某一场，用下面的「更换主打活动」。

### 更换主打活动

主打活动显示在活动页顶部的通栏横幅里，**全站只能有一场**。

1. 左侧「全站设置」→「壁纸、主打活动与平台入口」
2. 「主打活动」里从活动列表中选一场 → 保存

> **活动结束后不会自动下架**，需要在这里手动换成下一场。留空则整个横幅隐藏。
> 被主打的活动仍然正常出现在下方列表里，这是有意的：横幅是重点推荐，列表要保持完整。

### 新增一篇新生指南

1. 左侧「新生指南」→「New 指南」
2. **URL 短名**：英文小写加连字符，如 `arc-application`。**发布后不要再改**，
   改了会让别人分享出去的链接失效。
3. **摘要**：60 字以内，列表页和搜索结果显示的就是它。
4. **排序权重**：数字越小越靠前，留空排最后。指南有阅读顺序，请按顺序给权重
   （建议 10、20、30 这样留空隙，方便以后插入）。
5. 「最后更新」不用管，网站自动取最近一次保存的时间，对外只显示到月份。

### 更换首页壁纸

左侧「全站设置」→「首页壁纸」上传新图 → 保存。
**只需上传一张原图，不用自己压缩或切尺寸**——桌面版与移动版由系统自动生成，
访客的浏览器按屏幕宽度自动选择。

图片必须是学联自己拍的，或有明确授权，**不能用来源不明的网络图片**。

> 如果原图细节太密（例如大面积树叶、密集人群），压不到规定体积时**构建会失败**，
> 网站停在上一版、不会变成加载很慢的样子。这时换一张画面更简洁的照片即可。

### 修改首页简介 / 关于我们 / 合作与赞助

左侧「页面文案」，每个页面有中文与韩语两份，**两份都要改**。
韩语改动请找韩语流利的成员过目后再发布。

### 维护组织架构

左侧「组织架构」→ 选择部门 → 编辑。

**本页不放成员姓名与照片**，只呈现部门与小组结构。这样做有两个好处：
不涉及个人信息，不需要逐个征求同意与存档；部门结构相对稳定而人员每年更替，
去掉人员信息后这一页几乎不用随换届重做。对外联络需求由合作与赞助页的两张名片承担。

每个部门可以填：

- **排序**：数字越小越靠前。顺序按重要性排，首位留给对外或统筹职能的部门
- **会长团（通栏卡片）**：只有会长团打开，打开后卡片横跨整个页面宽度置于顶部
- **部门名称、职能描述**：中韩各一份。职能描述**控制在两行以内**
- **图标**：从下拉列表里选，不使用照片
- **下属小组**：中韩各一份。小组名称原则上不写职能说明，写长了卡片会变得很长

> 小组的调整（合并、新增）比部门频繁，直接在这里改即可，不需要找开发组。

### 维护合作与赞助页

左侧「页面文案」→「合作与赞助（中文／韩语）」：

- **开篇说明**：两三句话。**不要写各平台的粉丝数量**——数据放在对外提案材料里，
  在谈判场合呈现；写在页面上，数字一变就得改页面。
- **合作方式**：线上宣传与线下合作各三项，每项一个标题加一行说明。

左侧「全站设置」→「名片」维护会长与合作交流部部长的名片：

- **名片图片**：全站只有一版，图片本身同时包含中文与韩文，不随页面语言切换
- **职务**：中韩各一份，随页面语言切换
- **邮箱**：必须用**域名邮箱**（如 `president@yscssa.org`），转发到现任者的私人邮箱。
  换届时只改转发目标，页面不用动，也不会暴露任何人的私人邮箱
- **微信号**：建议用学联专用账号而非个人微信，随换届一并移交

> 名片图下方的邮箱与微信号文本**不能删**。图片里的字复制不了，
> 访客要一个字一个字手输，手机上尤其容易输错；搜索引擎和读屏软件也读不到图里的文字。

## 三、图片规范

上传前先压缩，否则手机打开会很慢。

| 用途 | 尺寸 | 格式 | 体积上限 |
|---|---|---|---|
| 首页壁纸（桌面） | 长边 2400px | WebP | 300KB |
| 首页壁纸（移动） | 长边 1200px | WebP | 120KB |
| 活动封面 | 16:9，长边 1600px | WebP | — |
| 名片 | 名片比例（约 910×550） | WebP | — |
| 其他图片 | 长边 ≤1600px | WebP | — |

**首页壁纸不用自己压**：后台上传一张原图即可，两种尺寸由系统生成（见上文「更换首页壁纸」）。
上表里的壁纸两行是系统生成后的结果，写在这里供核对。

压缩工具：[Squoosh](https://squoosh.app)（浏览器打开，选 WebP，调质量到 75 左右）。

**原图必须另存一份**到学联公共邮箱的云盘，按年份与活动分文件夹，作为组织档案长期保留。
仓库里只放压缩后的网页版本。

## 四、每年固定要做的事

| 时间 | 事项 |
|---|---|
| 成员离任后 1 周内 | 在仓库协作者列表中移除其账号 |
| 换届后 1 个月内 | 核对组织架构的部门与小组；更新两张名片的职务、邮箱转发与微信号 |
| 每场活动结束后 | 更换主打活动（不会自动下架） |
| 每学期开学前 | 复查新生指南，确认政策类信息与外部链接仍然有效 |
| 换届交接时 | 确认域名、托管、后台、仓库账号仍归属学联公共邮箱；
确认仓库仍有至少两名所有者，两步验证恢复码已归档 |

- [x] 五个页面在中韩两种语言下均可正常访问，URL 符合第二节规则（构建产物共 26 个 HTML）

      （`/about → /ko/about`、`/events → /ko/events`，逐页核对）

- [x] 新生指南可搜到中文关键词（「登录证」命中 2 篇，「宿舍」只命中 1 篇，
      说明是真的在过滤而不是回退显示全部）
- [x] 新生指南列表按排序权重排列，详情页显示最后更新月份

      （已知边界：中文 404 浏览器标签显示站点名而非「页面不存在」，见 README）

### 后台

以下各项需要先完成 GitHub OAuth 配置（见 README），再由学联管理员执行：

- [ ] 在后台完成以下操作全程无需修改代码：新增一场活动、新增一篇指南、
      更换首页壁纸、更换主打活动、修改首页简介
- [ ] 每位维护人员使用本人 GitHub 账号登录，后台仅显示 PRD 5.2 所列的可编辑项
- [ ] 移除一名成员后，该成员无法再登录后台，其余成员不受影响
- [ ] 内容保存后自动触发构建，两分钟内线上可见

> 开发组已验证：后台配置文件语法正确、能被 Sveltia CMS 正常加载，
> 且其字段与内容格式（schema）逐项一致——不一致会造成「后台存得下、构建却失败」。
